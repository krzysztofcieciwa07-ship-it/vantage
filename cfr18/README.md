# CFR-18 — Queue Resurrection

Isolated forensic exercise inside Vantage. It lives under `cfr18/` and does not modify the existing Vantage runtime.

## Run focused checks

```bash
cd cfr18
python3 -m pytest -q
python3 -m ci.evidence_vault verify
python3 -m ci.gen_incident --seed 12345
python3 -m ci.replay
```

## Run the live forensic scenario

The runner requires a separate participant submission file. It never derives the answer from the generated incident.

```bash
cd cfr18
CFR_PARTICIPANT_SUBMISSION=tests/fixtures/participant_submission_seed_12345.json \
USER_SEED=12345 \
sh scripts/live_forensic.sh
```

The checked-in submission is a **CI reference fixture**, not a human performance record. For a real participant run, supply a separately created JSON file with this shape:

```json
{
  "schema": "CFR-18/participant-submission-v1",
  "source": "participant",
  "fault_type": "double_process",
  "root_cause": "Describe the independently diagnosed cause and supporting signals.",
  "evidence_refs": ["data/events.jsonl#crash"],
  "reported_at": "2026-11-08T12:00:00+00:00"
}
```

Use the fault type that matches the observed incident; the example value above is not valid for every seed.

The hidden health-stability duration is read from `incident.json`. The probe runner records observations through that duration, and assertions plus scoring reject a short or unhealthy window. The scorer reports automated runtime recovery only. Operator investigation is not scored because this CI workflow does not capture an independent signed operator trace.

The local Evidence vault is tamper-evident, not immutable. Final forensic verification requires the external CI/Sigstore anchor generated by the workflow. No production authorization is created by a PASS or MERIT result.
