# CFR-18 — Queue Resurrection

Isolated forensic exercise inside Vantage. It lives under `cfr18/` and does not modify the existing Vantage runtime.

## Run focused checks

```bash
cd cfr18
python3 -m pytest -q
python3 -m ci.evidence_vault verify
python3 -m ci.gen_incident --seed 12345
python3 -m ci.replay
```

## Run the live forensic scenario

The runner requires a separate participant submission file. It never derives the answer from the generated incident.

```bash
cd cfr18
CFR_PARTICIPANT_SUBMISSION=tests/fixtures/participant_submission_seed_12345.json \
USER_SEED=12345 \
sh scripts/live_forensic.sh
```

The checked-in submission is a **CI reference fixture**, not a human performance record. It is used to validate the evidence pipeline and does not receive any diagnosis bonus. For a real participant run, supply a separately created JSON file with this shape:

```json
{
  "schema": "CFR-18/participant-submission-v1",
  "source": "participant",
  "fault_type": "double_process",
  "root_cause": "Describe the independently diagnosed cause and supporting signals.",
  "evidence_refs": [
    "data/events.jsonl#event=crash",
    "data/processed.jsonl#id=8"
  ],
  "reported_at": "2026-11-08T12:00:00+00:00"
}
```

Only `participant` and `CI_REFERENCE_FIXTURE` are valid source labels. Each evidence reference must use `relative/path.jsonl#field=value`, point to one of the incident's declared JSONL evidence files, and match a real record. References outside the permitted runtime evidence paths, path traversal, missing files, and unmatched records are rejected. The participant report is still a declared input, not an authenticated identity proof.

Use the fault type that matches the observed incident; the example value above is not valid for every seed.

The generated `incident.json` declares the final required runtime evidence paths: the Evidence chain, incident, manifest, probe results, separate participant submission, score result, processed data, and runtime events. Assertions check that each declared path actually exists. The external anchor and Sigstore signature are governed separately by `external_anchor_required` in the evidence manifest.

The scenario-specific required health-stability duration is read from `incident.json`. The probe runner records sub-second timestamps through that duration, and assertions plus scoring compare full-precision timestamps (rounding is display-only). They reject a short or unhealthy window, non-monotonic samples, or a gap longer than two seconds.

The score reports `probe_success_ratio`: the fraction of health probes that succeeded **inside the post-recovery stability window**. This is not end-to-end service availability or incident uptime. MTTR is marked `NOT_CAPTURED` because runtime events currently have no timestamps. Operator investigation is also not scored because CI does not capture an independent signed operator trace. The CI reference fixture is not awarded diagnosis points; a participant classification is separately graded only for a submission marked `source=participant`.

The local Evidence vault is tamper-evident, not immutable. Final forensic verification requires the external CI/Sigstore anchor generated by the workflow. No production authorization is created by a PASS or MERIT result.
